# Data Model: In-Memory Todo Console Application

**Feature**: 001-inmemory-todo-console
**Date**: 2026-01-01
**Status**: Complete

## Overview

This document defines the data model for the in-memory todo application. The model is designed to be simple, type-safe, and compatible with future database-backed implementations in Phase II.

## Entities

### Todo

Represents a single task in the todo list.

| Field | Type | Required | Default | Constraints |
|-------|------|----------|---------|-------------|
| id | int | Yes | Auto-generated | Positive integer, unique, immutable, never reused |
| title | str | Yes | - | Non-empty string |
| description | str | No | "" | Any string, can be empty |
| completed | bool | No | False | True = complete, False = incomplete |

**Python Definition**:
```python
from dataclasses import dataclass

@dataclass
class Todo:
    id: int
    title: str
    completed: bool = False
    description: str = ""
```

**Validation Rules**:
- `id`: Must be positive integer (>0)
- `title`: Must be non-empty after stripping whitespace
- `description`: No validation (empty allowed)
- `completed`: Boolean only

**State Transitions**:
```
[Created] --> completed=False
    |
    v
[Mark Complete] --> completed=True
    |
    v
[Mark Incomplete] --> completed=False
    |
    v
[Deleted] --> removed from store
```

### TodoStore

In-memory collection that manages Todo entities.

| Field | Type | Purpose |
|-------|------|---------|
| _todos | dict[int, Todo] | Maps ID to Todo entity |
| _next_id | int | Tracks next available ID (starts at 1) |

**Python Definition**:
```python
class TodoStore:
    def __init__(self):
        self._todos: dict[int, Todo] = {}
        self._next_id: int = 1
```

**Operations**:

| Operation | Input | Output | Description |
|-----------|-------|--------|-------------|
| add | title, description | Todo | Create new todo with auto-assigned ID |
| get | id | Todo \| None | Retrieve single todo by ID |
| get_all | - | list[Todo] | Retrieve all todos in insertion order |
| update | id, title?, description? | Todo \| None | Update existing todo fields |
| delete | id | bool | Remove todo by ID, return success |
| set_completed | id, completed | Todo \| None | Set completion status |

**Invariants**:
- `_next_id` always equals max(existing IDs) + 1 or 1 if empty
- IDs are never reused (even after deletion)
- `_todos` maintains insertion order (Python 3.7+ dict guarantee)

## Relationships

```
TodoStore (1) ----contains----> (*) Todo
```

- One TodoStore contains zero or more Todo entities
- Each Todo belongs to exactly one TodoStore
- TodoStore is the single source of truth for all todos

## Phase II Compatibility

The data model is designed for easy migration to SQLModel in Phase II:

```python
# Phase I (current)
@dataclass
class Todo:
    id: int
    title: str
    completed: bool = False
    description: str = ""

# Phase II (future)
from sqlmodel import SQLModel, Field

class Todo(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    title: str
    completed: bool = False
    description: str = ""
```

**Migration Notes**:
- Field names and types remain identical
- Only `id` changes from required to optional (auto-generated by DB)
- Business logic in `services.py` requires no changes
- Only `store.py` implementation changes (dict → database)

## Example Data

**Empty Store**:
```python
store._todos = {}
store._next_id = 1
```

**After Adding Two Todos**:
```python
store._todos = {
    1: Todo(id=1, title="Buy groceries", completed=False, description=""),
    2: Todo(id=2, title="Call dentist", completed=False, description="Schedule checkup")
}
store._next_id = 3
```

**After Completing Todo 1**:
```python
store._todos = {
    1: Todo(id=1, title="Buy groceries", completed=True, description=""),
    2: Todo(id=2, title="Call dentist", completed=False, description="Schedule checkup")
}
store._next_id = 3
```

**After Deleting Todo 1**:
```python
store._todos = {
    2: Todo(id=2, title="Call dentist", completed=False, description="Schedule checkup")
}
store._next_id = 3  # ID 1 is NOT reused
```
